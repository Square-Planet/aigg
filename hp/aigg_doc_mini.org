    * Incremental optimization schedules
      For the larger grids, there are two issues with running the described optimization procedure to obtain a target grid of maximum order $L$ directly:
      - First, we generally do not know what is the largest order $L$ which an optimized spherical integration rule could possibly realize for a given set of orbits. Consequently, it is not clear which $L$ to choose for optimizing
      - Second, obtaining an reasonable initial guess of the seed points, which makes it likely that the iterative optimization converges, can be rather difficult if the points have to be guessed ex nihilo.
  
    #+       Both problems can be addressed by running an _#incremental optimization schedule#_, instead of attempting to optimize the target rule for (unknown) target order $L$ directly.
    #+       As an example, consider the following process:
    #+       - Assume we have given an initial set of seed points $\{\vec r_q\}$, which are not necessarily obtained as result of any specific optimization.
    #+       - We may choose a (small) initial $L$, for which likely an exact integration rule can be obtained (in principle, even $L=0$).
    #+       - We can then repeat the following process:
    #+         - /#Step 1:#/ Optimize the seeds and weights for this target $L$.
    #+         - /#Step 2:#/ If at convergence $r$ is very close to numerical zero ($r<\text{thr-res}$, e.g., $r<10^{-25}$), then the integration rule is considered exact for order $L$.
    #+           - If the optimized rule is exact for order $L$, increase $L$ and go to /#Step 1#/
    #+           - If the optimized rule is not exact for order $L$, decrease $L$ to last known working $L$, re-optimize the points and weights, and exit.
    #+       That is, the parameters of the rule are optimized step by step, for increasingly large target orders $L$.
    #+       And this is done until an $L$ is found for which `aigg` is no longer able to determine a set of $\{\vec r_q\}$ which yield an exact numerical integration of the target space.
    #+       The advantages of this process are that (a) the target $L$ does not need to be known beforehand; rather, it is a result of the optimization process, and (b) at each $L$ step, the change in the distribution of points $\{\vec r_q\}$ is smaller than it would be if one were to optimize the rule for the target $L$ directly (without the interemediate steps); this simplfies convergence of the process.
      Both problems can be addressed by running an >#IncrementalScheduleSection#<{_#incremental optimization schedule#_}, instead of attempting to optimize the target rule for the (generally unknown) target order $L$ directly.
      In this case, one performs a series of optimizations with gradually increasing (or decreasing) $L$, each time using the result of the last optimization as starting guess.
    #+       So the parameters of the rule are optimized step by step, for increasingly large target orders $L$.
      - For an incremental upward search, this is done until an $L$ is found for which `aigg` is no longer able to determine a set of $\{(\vec r_q,w_q)\}$ which yield an exact numerical integration of the target space.
      - For an incremental downward search, this is done until the first $L$ is found which integrates exactly.
  
    #+       The advantages of this process are that (a) the target $L$ does not need to be known beforehand; rather, it is a result of the optimization process, and (b) at each $L$ step, the change in the distribution of points $\{\vec r_q\}$ is smaller than it would be if one were to optimize the rule for the target $L$ directly (without the interemediate steps); this simplfies convergence of the process.
  
      `aigg` supports both /#upward#/ and /#downward#/ incremental search schedules, and allows starting the schedule at arbitrary points and using arbitrary step widths, as well as performing a fixed set of additional operations once the breaking condition is met.
  
      Example input `inputs/1-incremental-search-up.ini`:
      #+BEGIN_PYTHON
      # Make an initial guess using a hexagonal grid with s=5 and t=1 parameters as
      # described by Ahrens & Beylkin. Then do a series of grid optimizations, each
      # time using the result of the last calculation as initial guess:
      #
      # - First optimize the points & weights of this grid for to minimize the
      #   residual for the monomials of degree l <= 4 ('[4,..]').
      # - Then keep on increasing l by +1 (step:+1) until we find the first l for
      #   which the optimized grid DOES NOT integrate the monomials of degree l
      #   exactly (in this case (the hex{5;1}-grid) this will be lfinal=30).
      # - Afterwards, optimize the grid for lfinal-1 ('..,-1]') (which is 29 in this
      #   case), using the converged, but non-exact solution for lfinal as starting
      #   guess. The resulting grid will be exact for order 29 again, but will in this
      #   case possibly show a somewhat better weight distribution
      { point-group: icosahedral;
        degree: [4,step:+1,-1];
        max-step: 1e4*residual;
        initial-points: hex-grid{5;1;01c}
      }
      #+END_PYTHON
      Example input `inputs/2-incremental-search-down.ini`:
      #+BEGIN_PYTHON
      # as 1-incremenal-search-up, but now search incrementally in DOWNWARD direction.
      # The first grid optimized will be of degree l=35. Then we decrease l by 1
      # (step:-1) until we find the first grid which integrates exactly.
      #
      # additionally, this config shows more fine-tuning options for the step size: by
      # default use a maximum step size of 10^4 times the current residual, but never
      # restrict the step size to maximum steps smaller than min:1e-9, and never allow
      # steps larger than 7e-4.
      #
      # In this case, this finds the same grid as the final result of the
      # 1-incremental-search-up.ini, but this may different in other cases.
      { point-group: icosahedral;
        degree: [35,step:-1];
        max-step: {1e4*residual; max:7e-4; min:1e-9};
        initial-points: hex-grid{5;1;01c}
      }
      #+END_PYTHON
      *#Comments:#*
      - Generally, incremental upward searches with steps of either $+1$ or $+2$ appear to be most useful.
      - For steps of two, it may be advisable to perform separate optimization runs starting at an even and at an odd initial $L$; e.g.,
        ```
        degree: [4,step:+2,-1,-2]
        ```
        and
        ```
        degree: [5,step:+2,-1,-2]
        ```
      - In an upward search, such as here, the entries `[…,-1,-2]` mean that after the $L_\mathrm{mx}$ is found which no longer integrates exactly, first attempt to optimize a rule with $L=(L_\mathrm{mx}-1)$. If this rule optimizes exactly $\Rightarrow$ exit. Otherwise, proceed with $L=(L_\mathrm{mx}-2)$. Each time the result of the last optimization is used as starting guess.
        Further schedule entries may be given for larger incremental step widths.
    * {Refining existing} integration {rules}
      `aigg` may be used to either >#RefineExistingRuleSection#<{verify or refine existing integration rules} supplied as input data in rather general formats.
  
      - If used in this way, `aigg` will read the initial seed points from an externally given text file, and use these as starting guess for a grid optimization.
        The input file is specified in the rather free form format described below (#(the weights, if given, are ignored)#),
  
      - The seed points may be given in terms of either Cartesian coordinates, or in terms of ^#https://en.wikipedia.org/wiki/Barycentric_coordinate_system#Barycentric_coordinates_on_triangles#^{barycentric coordinates} with respect to the ^#FundamentalRegionsSection#^{fundamental region}.
  
      Example input `inputs/3-refine-initial-grid.ini`:
      #+BEGIN_PYTHON
      # This time do the following:
      # - Read the initial cartesian points from a data file (e.g., a
      #   set of points made by previous runs of the grid optimization).
      #   The file here is called points 'inputs/312-guess.txt' (where
      #   'inputs' is the directory relative to the current directory).
      #
      #   Regarding the file format, the following conventions hold:
      #     * The first line of the file is ignored.
      #     * Of every other line, the first three elements separated by spaces
      #       are read as cartesian coordinates. The rest of the line is ignored
      #       (including possible weights, if given)
      #     * File reading ends once we encounter a line which cannot be read
      #       as three floating point numbers.
      #     * Lines startig with '#' or '//' are ignored.
      # - Then optimize a grid of degree 30 with these starting points, and
      #   use its result as initial guess for an optimization of degree 29.
      { point-group: icosahedral;
        degree: [30,29];
        max-step: {1e4*residual; max:7e-4; min:1e-9};
        initial-points: read-cartesian{inputs/points-312-guess.txt}
      }
      #+END_PYTHON
      Example input `inputs/4-refine-barycentric-coordinate-guess.ini`:
      #+BEGIN_PYTHON
      # as 3-refine-initial grid, but this time read the input positions as
      # barycentric coordinates of the fundamental region (for icosahedral,
      # tetrahedral, and octahedral grids this is a triangle in all cases). The inputs
      # is given in triples of tau0, tau1, tauC. What these mean depends on the point
      # group (see ConvertBarycentricToCartesian function).
      #
      # For icosahedral grids, both tau0 and tau1 refer to vertices of the
      # icosahedron, and tauC refers to the mid point ('c'entral point) of an
      # icosahedron face.
      #
      # The file format works as in the cartesian case: The first line is ignored, and
      # only the first three scalars are read as actual input. Reading stops once we
      # reach a line which does not start with three scalars.
      { point-group: icosahedral;
        degree: [step:+1,-1];
        max-step: 1e-3;
        initial-points: read-barycentric{inputs/barycentric-guess.txt}
      }
      #+END_PYTHON
  
    * {Exporting and visualizing} integration {rules}
      If the optimized rules are meant for further processing (or packaging),
      it is advisable to ask `aigg` to export the core information of the optimized grid to a separate data file, rather than attempting to parse it from the `aigg` standard output.
      Doing so also allows automatically retaining only the /#“best”#/ version of a rule encountered during a optimization schedule (see comments below).
      This is done using the `export` option as shown here:
  
      Example input `inputs/6-export-and-visualization.ini`:
      #+BEGIN_PYTHON
      # This file contains a command to export the final integration points to a data
      # file. With 'points: all', all symmetry-equivalent points will be explicitly
      # generated and exported (e.g., here, a general seed point leads to 60 exported
      # points, a seed point on a vertex leads to 12 exported points, etc).
      # Alternatively, one can give 'points:seeds', in which case only the unique
      # points are exported.
      #
      # If the required python packages are installed and a suitable graphics card
      # driver is present, the so-computed grid points can be visualized with
      #
      #     visualize_rule.sh ico-3-2.dat
      #
      # (use filename you used for export, here 'ico-3-2.dat')
      { point-group: icosahedral;
        degree: [15,step:+1,-1];
        max-step: 1e4*residual;
        initial-points: hex-grid{3;2;01c};
        export: {file: ico-3-2.dat; format: text; points: all}
      }
      #+END_PYTHON

    * {Making rules} by demanding {exact} integration of {polynomials}
      However, in one spatial dimension, there are many well-known integration rules which afford formally much more efficient ways of numerically approximating such definite integrals, provided the functions $f(x)$ they are applied to are known to have certain analytical forms or properties.

      In particular, so called >#GaussianQuadraturesSection#<{_#Gaussian quadrature#_ rules} are very successful and widely used.
      In a Gaussian quadrature of order $L$, the points $\{(x_g,w_g)\}$ are determined in such a way that
      \[ \int_a^b m_k(x)\,w(x)\,\d x = \sum_{g=1}^N m_k(x_g)\,w_g \]
      holds /#exactly#/ for all functions
      $m_k(x)$ ($k\in\{0,1,\ldots,L\}$) given by
      \[ m_k(x) = x^k. \]
      Such functions are called _#monomials#_.
      Here $w(x)$ is a (shared) weight function which has to fulfill certain formal conditions (in particular, $w(x)>0$ for all $x\in[a,b]$) -- in the simplest case, it may be given by the uniform weight $w(x)=1$ (#(and otherwise, in many application contexts a choice of weight function $w(x)$ arises more or less naturally)#).

      The conditions above mean that for the class of target functions
      \[ t_k(x):=m_k(x)\,w(x) = x^k\,w(x) \qquad(k\in\{0,1,\ldots,L\})
      \]
      the numerical and analytical integrals agree /#exactly#/ -- the numerical integral is in this case not an approximation, and we have
      \[[ \int_a^b t_k(x)\,\d x &=& \int_a^b m_k(x)\,w(x)\,\d x
      \\ &=& \sum_{g=1}^N m_k(x_g)\,w_g
      \\ &=& \sum_{g=1}^N \frac{t_k(x_g)}{w(x_g)}\,w_g
      \\ &=:& \sum_{g=1}^N t_k(x_g)\,\tilde w_g\qquad\text{where $\tilde w_g := w_g/w(x_g)$}.
      \]]
      However, integration is a /#linear operation#/: for any numbers $\alpha,\beta\in\spa{R}$ and functions $f(x)$ and $g(x)$, we have
      \[ \int_a^b \bigl(\alpha f(x) + \beta g(x)\bigr)\d x = \alpha  \int_a^b f(x)\,\d x + \beta  \int_a^b g(x)\,\d x.\]
      Consequently, any integration rule which exactly integrates all target functions $t_k(x) = x^k w(x)$ with $0\leq k\leq L$ will /#automatically#/ also exactly integrate all functions $t(x)$ given by
      \[ t(x) = P(x)\,w(x) = \sum_{k=0}^L c_k\,x^k\,w(x),\]
      as long as the polynomial $P(x)$ has a total degree of $L$ or less:
      \[ \int_a^b t(x)\,\d x = \sum_{g=1}^N t(x_g)\,\tilde w_g. \qquad\text{($=$, not $\approx$)}\]

      So if the actual functions $f(x)$ the rules are applied to then either /#are#/ such a weighted polynomials (or, more realistically, each $f(x)$ could be well approximated by one, in a certain sense),
      then these types of rules afford a very efficient numerical approximation of the integrals $\int_a^b f(x)\,\d x$.
      Concretely, making /#both#/ the $N$ grid points $\{x_g\}$ and the weights $\{w_g\}$ variable allows for exactly integrating all functions $t(x)=P(x)\,w(x)$ where $P(x)$ is a polynomial of up to a total degree of $L=2N-1$ -- for larger $N$ and well-behaved functions $f(x)$, this is (formally) significantly more efficient than numerical quadrature rules employing fixed points (like the midpoint rule mentioned above, or other Newton-Cotes formulas).

      The highest $L$ for which a integration rule will integrate all polynomials of degree $\leq L$ exactly is called the _#order#_ of the integration rule.

      Such Gaussian integration rules are closely related to classes of so-called /#orthogonal polynomials#/, which are defined by the weight functions $w(x)$ and the integration domain given by $a$ and $b$ (upper and lower integration limits, of which neither necessarily has to be finite).
      While one could, in principle, determine integration rules for just about any valid fixed combination of number of grid points $N$, weight function $w(x)$, and integral domain $[a,b]$, in general this has to be done numerically.

      However, in the one-dimensional case, the term “Gaussian quadrature” is most closely associated with
      various special classes of weight functions $w(x)$, for which closed formulas are known which allow computing the set of grid points $\{(r_g,w_g)\}$ for any given number of points $N$.
      For example:
      + /#Gauss-Hermite quadrature:#/ Here the integration domain is $[-\infty,\infty]$, and weight function is $w(x)=\exp(-x^2)$, such that we have
        \[ \int_{-\infty}^{\infty} m_k(x)\,\exp(-x^2)\,\d x = \sum_{g=1}^N m_k(x_g)\,w_g \]
        for all monomials $m_k(x)=x^k$ ($k\in\{0,1,\ldots,L\}$) and degree $L=2N-1$.
        As explained above, this implies that for all functions $f(x)$ of the form
        \[ f(x) = P(x)\,w(x) = \sum_{k=0}^L c_k\,x^k\exp(-x^2), \]
        where $P(x)$ is a polynomial of degree $\leq L$, we get
        \[ \int_{-\infty}^{\infty} f(x)\,\d x = \sum_{g=1}^N f(x_g)\,\tilde w_g \qquad\text{where}\quad \tilde w_g := \frac{w_g}{w(x_g)} \]
        That is, for all such functions $f(x)$, the integral approximation afforded by the Gauss-Hermite integration rule is /#exact#/; and, as explained above, for functions which are not necessarily of the exact form $f(x)=P(x)\,w(x)$ given above, but which can be efficiently approximated by such functions, the rule would be expected to provide efficient approximations.

        (#(Note: we distinguish $w_g$ and $\tilde w_g=w_g/w(x_g)$ because in the numerical literature, such rules are commonly written with the weight function $w(x)$ appearing separately in the lhs integral, rather than as part of $f(x)$ as explained above.)#)
      + /#Gauss-Laguerre quadrature#/: Similar to Gauss-Hermite quadrature, but for
        \[ \int_{0}^{\infty} m_k(x) \exp(-x)\d x = \sum_{g=1}^N m_k(x_g)\,\tilde w_g \]
      + /#Chebychev-Gauss#/: Similar to Gauss-Hermite quadrature, but for
        \[ \int_{-1}^{+1} \frac{m_k(x)}{\sqrt{1-x^2}}\,\d x = \sum_{g=1}^N m_k(x_g)\,\tilde w_g \qquad\text{(Type 1)}\]
        or, alternatively,
        \[ \int_{-1}^{+1} m_k(x) \sqrt{1-x^2}\,\d x = \sum_{g=1}^N m_k(x_g)\,\tilde w_g \qquad\text{(Type 2)}\]

    * Integration rules in higher dimensions
      The idea of approximating integrals by such finite sums can be readily generalized to more involved cases.
      For example, rather than integrating just over intervals $[a,b]$ on the real axis, on may wish to integrate functions $f(\vec r)$ over integration domains $\Omega$ given by more complex manifolds (e.g., the surface of the three-dimensional unit sphere, which is a two-dimensional subset of $\spa{R}^3$).
      
      Also, one may again want to apply a non-uniform weight $w(\vec r)>0$ to different points $\vec r\in \Omega$ on the manifold $\Omega$ defining our integration domain.

      >#IntegrationRulesHigherDimSection#<{In this case,} one may simply replace the ^#IntegrationRulesOneDimSection#^{1D integration rule above} by
      \[ \int_\Omega f(\vec r)\,w(\vec r)\,\d\Omega \approx \sum_g f(\vec r_g)\,w_g.\]
      In this, $N$ is again the number of _#grid points#_ $\vec r_g$ ($g\in\{1,2,\ldots,N\}$), on which the function $f(\vec r)$ is explicitly evaluated to form the approximate integral on the rhs.
      The only formal difference is that the grid points $\vec r_g\in\Omega$ are now part of a (possibly multi-dimensional) manifold $\Omega$ (e.g., a subset of some $\spa{R}^D$).
      As in the case of one-dimensional quadratures before, the
#+       $\{w_g;\,g\in\{1,2,\ldots,N\}\}$
      $w_g\in\spa{R}$ ($g\in\{1,2,\ldots,N\}$) denote the _#grid weights#_ associated with each point $r_g$, while the function $w(\vec r)$ (not to be confused with the grid weights $w_g$) denotes a _#weight function#_, which assigns to every points $\vec r\in \Omega$ a non-negative weight $w(\vec r)\in(0,\infty)$ (#(and, ^#GaussianQuadraturesSection#^{also as before}, the function $w(\vec r)$ is typcally chosen by a user, and which one to choose often arises naturally from the context of a given application.       This more general formula reduces to the formula discussed in one dimensional case if $\Omega$ is chosen as the real interval $[a,b]$ and the weight function is chosen as $w(x)=1$ uniformly.

      So, what is a /#“spherical integration rule”#/ (aka: an /#angular integration grid#/)?
      It is just an integration grid in the sense described ^#IntegrationRulesHigherDimSection#^{earlier}, which allows for approximating integrals over functions defined on the unit sphere $\spa{S}_2$.
      Concretely, it is a set of $N$ grid points and weights $\{(\vec r_g,w_g);\,g\in\{1,2,\ldots,N\}\}$ (with each grid point $\vec r_g$ itself lying on the unit sphere), combined with the implicit understanding that the points and weights are used with the following finite approximation of integrals:
      \[ \int_{\spa{S}_2} f(\vec r)\,\d\Omega \approx \sum_{g=1}^N f(\vec r_g)\,w_g.
      \]
      The left hand side integral hereby only involves the sphere surface itself; the $\spa{R}^3$ vector $\vec r$ used as integration variable never leaves the unit sphere in this case.
      A common way to ensure this, as well a as common way of describing functions which are defined only on the sphere (surface), is to introduce ^#https://en.wikipedia.org/wiki/Spherical_coordinate_system#^{spherical coordinates} $(\theta,\phi,r)$, which are related to the Cartesian coordinates by
      \[[ x &=& r \sin(\theta) \cos(\phi)
      \\  y &=& r \sin(\theta) \sin(\phi)
      \\  z &=& r \cos(\theta).
      \]]
      Here $\phi\in[0,2\pi]$, $\theta\in[0,\pi]$ and the radial coordinate $r$ is redundant, because for $(x,y,z)\in\spa{S}_2$, it is uniformly $r=1$.
      Therefore both points on the unit sphere, and the corresponding integrations (especially analytical ones), are also commonly described in terms of $(\theta,\phi)$ coordinates only, rather than in terms of $(x,y,z)$ coordinates restricted to $x^2+y^2+z^2=1$.

      When writing integrations, we have to take into account the non-linearity of the spherical to Cartesian coordinate transformation, which requires a transformation of the Cartesian volume elemement $\d x\,\d y\,\d z$ over flat space $\spa{R}^3$ into a coordinate-dependent volume element as follows:
#+       which yield a transformed volume element of
      \[ \d^3 \vec r = \d x\,\d y\,\d z = r^2 \sin(\theta)\,\d r\,\d\phi\,\d \theta. \]
      (#(This comes from the ^#https://en.wikipedia.org/wiki/Volume_element#^{determinant of the Jacobi matrix of the transformation} $(r,\theta,\phi)\rightarrow(x,y,z)$)#).
      Using this volume element, and inserting the transformation formulas above for $f(\vec r)=f(x,y,z)$,
      one may then explicitly write the analytical spherical integration from above as follows:
      \[ \int_{\spa{S}_2} f(\vec r)\,\d\Omega = \int_{0}^\pi\int_0^{2\pi} f\bigl(\sin(\theta) \cos(\phi),\,\sin(\theta) \sin(\phi),\,\cos(\theta) \bigr)\sin(\theta)\,\d\phi\,\d\theta \]
#+       \[ \int_{\spa{S}_2} f(\vec r)\d\Omega = \int_{0}^\pi\int_0^{2\pi} f(x=\sin(\theta) \cos(\phi),y=\sin(\theta) \sin(\phi), z=\cos(\theta) )\sin(\theta)\,\d\phi\,\d\theta \]
      In the case that $f(x,y,z)$ can be evaluated in terms of the angles $f(\theta,\phi)$ directly, this simplifies to
      \[ \int_{\spa{S}_2} f(\vec r)\,\d\Omega = \int_{0}^\pi\int_0^{2\pi} f(\theta,\phi)\sin(\theta)\,\d\phi\,\d\theta.
      \]
      Note that in either case, the two dimensional integration over the manifold $\Omega=\spa{S}_2\subset \spa{R}^3$ is replaced two /#separated one-dimensional integrations#/ over $\theta$ and $\phi$ indiviually.
      This is formally a significant simplification.

      The price one has to pay for that  is that the description of space is no longer rotationally invariant: there is now one direction in space, the $z$ axis, which is explicitly chosen by a user and treated differently from the other two.
      This is no issue as long as all calculations are done exactly; however, in numerical treatments, there are always approximations, and an artifical unbalanced treatment of different directions in space (as would result from approximating the $\theta$ and $\phi$ integrations independently of each other), can lead to calculation artifacts, as well as to reduced calculation efficiency.
      A central motive of the integration rules considered on this site is therefore the circumvention (or at least reduction) this problem by making them as rotationally invariant (i.e., as uniform in their treatment of space directions) as possible with a fixed finite number of numerical calculations -- this is why we construct integration rules of polyhedral symmetry, with nonlinear numerical optimizations, based on the described theory, rather than just using the indicated formula in terms of spherical coordinates.

      * Order from spherical harmonics
        Combined, the listed properties of spherical harmonics imply a natural definition of the _#order of a spherical integration rule#_ as follows:
        ⟨newline⟩
        > The order $L$ of spherical integration rule $\{(\vec r_g,w_g)\}$ is defined as the largest integer $L$ for which it integrates all spherical harmonics $Y_{lm}$ with $l\in\{0,1,\ldots,L\}\leq L$ (i.e., with $l\leq L$) and all $m\in\{-l,-(l-1),\ldots,(l-1),l\}$ (i.e., with $-l\leq m\leq l$) ***exactly***:
        > \[ \forall l\leq L,\;\forall -l\leq m \leq l:\quad\int_{\spa{S}_2} Y_{lm}(\theta,\phi)\,\d\Omega = \sum_{g=1}^N Y_{lm}(\theta_g, \phi_g)\,w_g.
        > \]
        > In this, $\theta_g$ and $\phi_g$ denote the angles of $\vec r_g$ expressed in spherical coordinates.
        ⟨newline⟩
        This is, indeed, the standard definition of the term /#order#/ of a spherical integration rule.
        However, `aigg` does not employ spherical harmonics, but rather a criterion expressed in terms of Cartesian monomials, which can be shown to be equivalent.

      * Resolution of the {Dirac delta} distribution {in} terms of {spherical} series {expansions}
        By definition, a spherical integration rule of order $L$ can exactly integrate all functions
        \[ \tilde f(\theta,\phi) = \sum_{l=0}^L\sum_{m=-l}^{l} c_{lm} Y_{lm}(\theta,\phi) \]
        written in the spherical expansion introduced ^#SphericalSeriesExpansionFormal#^{last section}.
        To get an impression of what this /#means#/; in particular, of what kind of spatial resolution an integration rule must be able to handle to support an order of $L$, we can ask ourselves: what are the limits of which kinds of functions such an order $L$ expansion could possibly represent?
        What is the /#worst#/ function one could possibly apply it to?
        To do so, one can consider the accuracy of the expansion of the /#least spherically uniform#/ /#“function”#/ one could possibly imagine, in terms of spherical harmonics: the Dirac $\delta$-distribution.

        * The spherical Dirac delta distribution
          Let $\vec z\in \spa{S}_2$ denote one fixed point on the sphere.
          The associated (two-dimensional, spherical) ^#https://en.wikipedia.org/wiki/Dirac_delta_function#^{Dirac $\delta_{\vec z}$-distribution} then is a $\delta_{\vec z}(\vec r):\;\spa{S}_2\mapsto \spa{R}$ function-like object, which is characterized by the following two properties:
          - $\delta_{\vec z}(\vec r)$, more conventionally written as “$\delta(\vec r - \vec z)$”, yields a value of /#exactly zero#/ for all function arguments $\vec r\in\spa{S}_2$ which do not coincide with the fixed point $\vec z\in\spa{S}_2$. That is,
            \[ \forall\vec r\in\spa{S}_2 \text{ with } \vec r\neq \vec z:\quad\delta(\vec r-\vec z)=0 \]
          - $\delta_{\vec z}(\vec r)$ yields a value of $+\infty$ for $\vec r=\vec z$ in exactly such a way that for /#any#/ (normal) spherical function $f:\spa{S}_2\mapsto \spa{C}$ the following identity holds:
            \[ \int_{\spa{S}_2} f(\vec r)\,\delta(\vec r - \vec z)\,\d\Omega = f(\vec z) \]
            (#(more formally, this is not a mathematical result, but rather the actual definition of the $\delta$ distribution; where the real mathematics are involved is defining a ^#https://en.wikipedia.org/wiki/Measure_(mathematics)#^{formal framework} supporting such objects as Dirac-$\delta$ in a non-contradictory and well-defined way. Note that for common standard definitions of integrals, the lhs integral would be either zero or ill-defined if $\delta(\vec r-\vec z)$ were treated as a regular $\spa{S}_2\mapsto \spa{R}\cup\{\pm \infty\}$ function, but certainly not equal to the value of any generic integrand $f$ at a /#single point#/ $\vec z$)#)
          So $\delta(\vec r-\vec z)$ carries its entire integration weight in a single point $\vec z\in\spa{S}_2$, and is zero everywhere else.
          It is the very embodiment of the concept of a /#“least spherically uniform function”#/!

        * Maximally localized functions of order L
          So what do we obtain when we attempt to represent this object in terms of a spherical series expansion of finite order $L$?
          The resulting function $\tilde f(\theta,\phi)$ should then provide us with the most $\delta$-like object (in a least squares sense), and thereby least spherically uniform function, which a spherical expansion of order $L$ just /#barely#/ can still represent while concentrating the spread of $\tilde f(\theta,\phi)$ as closely as possible to a single given point $\vec z$ on the sphere.

          So let us obtain the functions $\tilde f(\vec r; \{\vec z, L\})$ -- each a function of argument $\vec r\in\spa{S}_2$ which parametrically depends on the target point $\vec z\in\spa{S}_2$ and the expansion order $L$ -- by fitting them to Dirac $\delta$-distributions.
          In the ^#SphericalSeriesExpansionFormal#^{previous section} we stated that the corresponding least-squares function fit
          \[ \tilde f\bigl(\theta,\phi; \{\vec z,L\}\bigr) = \sum_{l=0}^L\sum_{m=-l}^{l} c_{lm} Y_{lm}(\theta,\phi) \]
          to a target function $f(\theta,\phi)$ is obtained with the expansion coefficients $c_{lm}$ given by
          \[c_{lm} =  \int_{0}^{\pi} \int_{0}^{2\pi} \bigl(Y_{lm}(\theta,\phi)\bigr)^* f(\theta,\phi)\,\sin(\theta)\,\d\theta\,\d\phi. \]
          In the current case of $f(\vec r)$ replaced by $\delta(\vec r-\vec z)$, this integral is trivial to evaluate; by the definition of Dirac-$\delta$, it simply yields
          \[c_{lm} =  \bigl(Y_{lm}(\vec z)\bigr)^* = \bigl(Y_{lm}(\theta_z,\phi_z)\bigr)^*, \]
          where $\theta_z,\phi_z$ denote the spherical coordinates of $\vec z$.
          Consequently, we directly obtain
          \[ \tilde f\bigl(\theta,\phi; \{\vec z,L\}\bigr) = \sum_{l=0}^L\sum_{m=-l}^{l} \bigl(Y_{lm}(\theta_z,\phi_z)\bigr)^{*} Y_{lm}(\theta,\phi) \]
          as a closed-form analytic expression for the function most localized on a single point $\vec z\in\spa{S}_2$ which a $L$'th order spherical expansion could possibly represent.

        We next argue that using either set of functions is mathematically equivalent:
        - Let use define a _#spherical Cartesian monomial#_ as the function $m_{ijk}(\vec r):\;\spa{S}_2\mapsto \spa{C}$
          \[ m_{ijk}(x,y,z) := x^i y^j z^k.\]
          That is, the functional form of the spherical Cartesian monomials is identical to the regular $\spa{R}^3$ monomials -- they just map $(x,y,z)$ to the corresponding coordinates raised to the $i$th, $j$th, and $k$th power.

          \[ \abs{m_{ijk}} := i + j + k.\]

          \[ M_{\leq L} := \{ m_{ijk};\, i+j+k \leq L\},\]
          and $M_{-1} := \{\}$ (i.e., as empty set).

        - Theorem: Let $L\geq 0$ be a given integer, and let a spherical integration rule
          \[ \int_{\spa{S}_2} f(\vec r)\,\d\Omega = \sum_{g} f(\vec r_g)\,w_g \]
          be exact for all spherical Cartesian monomials
          \[ m_{ijk}\in M_{L}\cup M_{L-1}.
          \]
          (i.e., all $m_{ijk}$ with $i+j+k$ either $L$ and $L-1$).
          Then the following holds:
          - The integration rule is also exact for all $m_{ijk}\in M_{\leq L}$ (i.e., for all $m_{ijk}$ with $i+j+k\leq L$).
          - The integration rule is also exact for all spherical harmonics in the set
            \[ \{ Y_{lm};\; l\leq L, -l\leq m \leq l \}. \]
          That is:
          /#A spherical integration rule which exactly integrates all monomials of degree $L$ and $L-1$, is automatically of order $L$ in both the spherical monomials sense and the spherical harmonics sense#/.
        - The reverse implication also holds: an integration rule of order $L$ in the spherical harmonics sense integrates all monomials of degree $\leq L$ exactly.

          So in the future we will no longer distinguish the different characteristics of _#order#_ of a spherical integration rule.

        - For spherical monomials, exactness of a rule for $M_{L}$ and $M_{L-1}$ implies
          its exactness for all $M_{L'}$ with $L'\leq L$:
          Approach: downward induction. Let $L\geq 2$ and rule be exact for $M_L$. Then by the following argument, it is also exact for $M_{L-2}$:
          Let $m\in M_{L-2}$. Then
          \[[(x^2+y^2+z^2)\,m_{ijk}(x,y,z) &=& x^2 m_{ijk}(x,y,z) + y^2 m_{ijk}(x,y,z) + z^2 m_{ijk}(x,y,z)
          \\ &=& m_{(i+2)jk}(x,y,z) + m_{i(j+2)k}(x,y,z) + m_{ij(k+2)}(x,y,z)
          \]]
          All monomials on the rhs lie in $M_L$, and are therefore integrated exactly (because all $M_L$ functions are by premise).
          As both the analytical integration and the integration rule are linear, this implies the lhs expression $(x^2+y^2+z^2) m_{ijk}$ is also integrated exactly.
          However, for points of its domain, namely all $(x,y,z)\in \spa{S}_2$, we have
          \[ x^2+y^2+z^2=1.\]
          So for the lhs, we get
          \[ (x^2+y^2+z^2)\,m_{ijk}(x,y,z) = m_{ijk}(x,y,z)\]
          and therefore $m_{ijk}\in M_{L-2}$ is exactly integrated, too, if the rule is exact for all $m\in M_{L}$.

        - Next: all spherical harmonics $Y_{lm}$ can be written as linear combination in terms of monomials $m_{ijk}$ with $i+j+k=l$; since the $m_{ijk}$ are integrated exactly, so are the $Y_{lm}$.

          Reverse direction (exactness for $Y_{lm}$ implies exactness for monomials): Dimensional argument:
          - $Y_{lm}$ can be written as $l$'th degree polynomial in $x,y,z$.
            For each $l$ there will be a $k_l$ such that either $2k_l+l=L$ or $2k_l+l=L-1$.
            Consequently, set entry in
            \[ \bigl\{r^{2k_l} Y_{lm};\,m\in\{-l,\ldots,+l\}\bigr\}, \]
            can be written as Cartesian polynomial of either $L$th or $L-1$th order.
            However, on the sphere, $r^2=1$, so the resulting functions are /#identical#/ to the original $Y_{lm}$ if restricted to the sphere; in particular, they are still linearly independent.
          - The monomials $M_{L}\cup M_{L-1}$ are linearly independent.
          - There are exactly as many $\{Y_{lm}\}$ with $l\leq L$ as there are monomials in $M_{L}\cup M_{L-1}$.
          - So we have two vector spaces of identical dimension, and one (the monomials) spans the other (the harmonics). That only works if the harmonics also span the monomials.
          - $\Rightarrow$ exactness for $Y_{lm}$ implies exactness for monomials.

          In total: It's the same. Can use monomials to optimize, too.

    * {Seed points} of a symmetric integration rule
      - To characterize each integration rule, we use only an “irreducible” subset of information: namely the set of “seed points” of the integration rules.
        However, the actual integration rules always contain the full orbits of each seed point (and each point on the orbit generated from a seed point is assigned equal weight).
      - The seed points are symmetry unique points of the rule; or, in group theory language:
        For each point $\vec r_i\in\spa{R}^3$ of the actual rule, there is only a single canonical representative $\vec r_q\in\spa{R}^3$ of the group orbit
        \[ \groupname{G}(\vec r_q) = \bigl\{\groupelement{g}(\vec r_q);\,\groupelement{g}\in\groupname{G}\bigr\}\]
        in which $\vec r_i$ is contained.
      - However, note that the actual /#orbit length#/ of the seed point, that is the number of points it actually contributes to the integration rule, may be smaller than the number of group elements $\abs{\groupname{G}}$ in the case in which the seed point lies ^#SpecialOrbitsSection#^{on a special orbit}.
        Generally, integration rules including special orbit points appear to be more efficient than integration rules which do not include any special orbit points.
      - From the seed points, the weights and corresponding orbit types can be automatically generated.

    * Types of orbits
      * What is a group orbit?
        Let $\groupname{G}$ denote one of the polyhedral point groups.
        - *#The group elements $\groupelement{g}\in\groupname{G}$ map the unit sphere onto itself:#*
          The group elements $\groupelement{g}\in\groupname{G}$ are symmetry operations which map $\spa{R}^3$ space onto itself.
          This means that for any vector $\vec r\in\spa{R}^3$, there is a well defined
          \[ \vec r' = \groupelement{g}(\vec r) \qquad(\in \spa{R}^3) \]
          obtained by applying the group operation $\groupelement{g}$ to the point represented by $\vec r$.
          As each $\groupelement{g}\in\groupname{G}$ is a /#symmetry operation#/ mapping the polyhedron onto itself, it is, in particular, also an /#isometric operation#/. This means that it preserves the norm of the the points it is applied to:
          \[ \forall \vec r\in\mathbb{R}^3:\;\norm{\vec r'} = \norm{\groupelement{g}(\vec r)}. \]
          Consequently, it maps points on the unit sphere $\spa{S}_2$ onto other points on the unit sphere.
        - For a given point $\vec r\in\spa{S}_{2}$, the _#group orbit#_, called $\groupname{G}(\vec r)$, is defined as
          \[ \groupname{G}(\vec r) = \bigl\{\groupelement{g}(\vec r);\,\groupelement{g}\in\groupname{G}\bigr\}\]
          That is, it is the /#set of points obtained by applying every symmetry operation $\groupelement{g}\in\groupname{G}$ to the initial point $\vec r$#/.
      * Why are there multiple types of orbits?
        - With the previous definition, one might expect that a group orbit $\groupname{G}(\vec r)$ always has a length of $\abs{\groupname{G}}$; that is, that it has as many points as there are symmetry operations in the point group $\groupname{G}$.
        - However, this is not necessarily the case.
          The reason is that for a given point $\vec r\in \spa{S}_2$, it may happen that multiple different $\groupelement{g}\in\groupname{G}$ yield /#identical#/ transformed points.
          In this case, the group orbit $\groupname{G}(\vec r)$ will be smaller than $\abs{\groupname{G}}$.

          This is effect is most easily demonstrated in one dimension:
          - Consider the group $\groupname{G}=\{\groupelement{i}, \groupelement{\sigma}_x\}$, acting on $x\in\spa{R}$.
            Here $\groupelement{i}$ denotes the identity operation defined by
            \[ \forall x\in\spa{R}:\; \groupelement{i}(x) := x\]
            and $\groupelement{\sigma}_x$ the denotes /#“invert the $x$-coordinate”#/-operation defined by
            \[ \forall x\in\spa{R}:\; \groupelement{\sigma}_x(x) := -x. \]
          - For any point $x\in\spa{R}$, the group orbit then is
            \[ \groupname{G}(x) = \{ \groupelement{i}x, \groupelement{\sigma}_x \} = \{x, -x\}. \]
            For almost all points $x\in\spa{R}$, the group orbit $\groupname{G}(x)$ then will have length of $\abs{\groupname{G}(x)}=2$, which is equal to the number of group elements (=symmetry operations) in $\groupname{G}$.
          - However, for the single special point $x=0$, the transformed points $x$ and $-x$ making up the group orbit are /#identical#/.
            Therefore, the set $\{x, -x\}$ defining the group orbit $\groupname{G}(x)$ has only one distinct element, which is $x=0$ itself.
            So we obtain $\abs{\groupname{G}(x)}=1$ in this case.
          For the case of three-dimensional polyhedra, there are multiple different types of such orbits (#(up next)#).
        - We denote orbits with $\abs{\groupname{G}(\vec r)}<\abs{\groupname{G}}$ as _#special orbits#_, and orbits with $\abs{\groupname{G}(\vec r)}=\abs{\groupname{G}}$ as _#general orbits#_.
        - Special orbits need to be handled with care, because a point on a special orbit generally has a smaller number of geometric degrees of freedom than a general orbit, which means that the number of geometric parameters, which are optimized during an iterative grid optimization, is correspondingly reduced.
          However, almost all of the best integration rules we managed to construct so far included points on special orbits.
